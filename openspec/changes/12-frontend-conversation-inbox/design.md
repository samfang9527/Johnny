# Design: Frontend Conversation and Agent Inbox

## Design Status

Discussion required before implementation.

## Approach

Keep Conversation and Agent Inbox as separate product surfaces:

- Conversation handles user-initiated questions and ambiguous reasoning.
- Agent Inbox handles proactive recommendations generated by jobs, events, or agent runs.

Use Vue, Vite, and TypeScript. Reuse shared Vue components and composables from the Today/Calendar feature for recommendation cards, evidence rendering, and API calls.

Conversation UI:

- Thread list
- Message history
- Composer
- Evidence blocks in agent responses
- Proposed action cards

Agent Inbox UI:

- Pending and historical recommendations
- Priority indicators
- Evidence summary
- Accept, reject, edit, discuss actions

## Design Decisions

- Do not expose multiple agents in the UI.
- Reuse recommendation cards and evidence components from Today.
- Discuss opens a conversation linked to the recommendation.
- Inbox should support pending, accepted, rejected, edited, expired, and applied states.

## Testing Strategy

- Vue component tests for conversation thread loading and message submit.
- Vue component tests for response evidence rendering.
- Inbox list and empty state tests.
- Recommendation action tests shared with Today.
- Navigation tests from inbox recommendation to conversation.

## Risks

- If Conversation dominates the UI, Johnny may feel like a chatbot clone. Today remains primary.
- If Inbox and Today use different action patterns, decisions will feel inconsistent.
