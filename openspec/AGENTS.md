# OpenSpec Agent Instructions

## Required Workflow

- Work on one change folder at a time.
- Read `feature.md`, `proposal.md`, `specs/*/spec.md`, `design.md`, and `tasks.md` before proposing implementation.
- Do not start implementation until the product owner approves the current change's `design.md`.
- Keep changes testable and scoped to the capability named by the folder.
- Mark `tasks.md` checkboxes only after the described work is complete and verified.

## Documentation Shape

Each MVP change folder contains:

- `feature.md`: product/development summary for human discussion
- `proposal.md`: OpenSpec why/what/impact
- `specs/<capability>/spec.md`: OpenSpec behavioral delta
- `design.md`: technical approach requiring approval before implementation
- `tasks.md`: small, testable implementation steps
