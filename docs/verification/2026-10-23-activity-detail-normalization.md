# Task 3 — Activity detail normalization boundary

Task 3 adds Garmin JSON and original FIT normalizers plus a Garmin adapter method. No activity was fetched, backfilled, analyzed, or published during this task.

JSON laps, typed splits, split summaries, and heart-rate zones retain distinct `source_kind` values. Typed splits and summaries are overlapping/aggregate views, not additional distance or duration. `select_execution_evidence` picks one segment source and one sample source, preferring an integrity-checked FIT recording where available. JSON laps and chart samples cannot claim an exact Workout Step link.

Original FIT is decoded in memory from one bounded ZIP member. The decoder checks archive/member/decompressed limits, rejects traversal names, checks FIT integrity with a fresh stream before decoding, and drops location, identity and device fields. Timer start/stop events mark paused samples; lap timer and elapsed durations remain separate. A repeated `wkt_step_index` receives a repeat occurrence only when a corresponding Workout Step message and a defensible manual or matching timed boundary exist. Automatic distance laps remain unmapped.

The three real-account samples in [Task 1's contract report](2026-10-22-activity-detail-probe.md) expose descriptor keys and factors but do not establish a conversion formula. An independent Garmin Connect protocol investigation likewise warns that `factor` must not be applied uniformly ([source](https://github.com/awronski/gconnect/blob/main/GARMIN_CONNECT_PROTOCOL.md#34-units)); the local comparison test demonstrated that a single divide-by-factor rule incorrectly scales speed. Task 3 therefore stores recognized chart duration, distance and speed values as raw values with their unit metadata, and marks normalized channels unavailable. It does normalize heart rate when the descriptor is `bpm/1`. Charts remain partial evidence and the execution selector excludes their uncalibrated samples from interval analysis. The configured local database was unavailable for that calibration; no personal raw trace was saved in fixtures.

The adapter uses one authenticated client for a bounded detail session, requests chart data with `maxchart=2000, maxpoly=0`, downloads the `ORIGINAL` FIT format, and persists the refreshed session with the existing encrypted credential path after successful work. Its required `provider_activity_id` keeps the Garmin lookup distinct from the local `NormalizedDetails.activity_id` required by the Task 2 repository.
