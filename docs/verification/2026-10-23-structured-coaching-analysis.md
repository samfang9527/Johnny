# Structured coaching analysis, Task 8

Task 8 adds a shared `coaching-analysis-v2` result for workout advice and daily review. The model receives a bounded catalog of deterministic execution facts, dated recovery signals, the selected workout state, and allowed action IDs. The prompt omits activity names, workout purpose/Coach Note, raw samples, FIT files, and GPS. It requests observation → interpretation → action in Traditional Chinese. The model cannot supply an Execution Score or a canonical workout change.

The response parser accepts only one strict JSON object with short text and at most three findings, actions, and limitations. Evidence references must exist in the catalog; each numeric statement must cite an exact fact value **and unit**. Unsupported causal guarantees, score text, Markdown/HTML, unknown fields, fabricated references, and unauthorized actions fall back to a structured rules result. The fallback uses the same deterministic findings when available, distinguishes incomplete evidence from model failure, and identifies no-plan, rest-day, completed, unpaired, and unplanned states. It records a safe reason category without provider error text. OpenAI transport disables SDK retries and limits each attempt to 20 seconds; the application makes at most two attempts.

The fixed test set covers valid JSON, fenced/invalid/oversized responses, unknown fact and action IDs, ungrounded numbers, causal and canonical-change claims, malicious workout text, timeout/provider failure, incomplete recovery, seven execution cases (longer cooldown or work block, incomplete intervals, auto laps, pauses, sampled charts, missing heart rate), and bounded prompt context. Validation and these fixtures constrain the model but **cannot mathematically guarantee every natural-language interpretation is true**. A later workflow task must still persist provenance and run end-to-end acceptance tests with actual evidence before enabling this result in the product.
