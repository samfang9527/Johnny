# Task 5 — Traceable activity execution analysis

Task 5 compares committed activity details with the Prescription Snapshot effective at training time. The new `ExecutionAnalysis` contains a stable fingerprint, historical prescription revision, current detail snapshot IDs, versioned facts, findings and limitations. It does not change the seven-day `execution-v1` score or publish coaching text.

Workout Steps inside Repeat Blocks expand to stable `(step_path, repeat_occurrence)` identities. A FIT lap receives an `exact` step mapping only when its explicit FIT step index, occurrence, order, timer boundary and embedded planned duration/distance agree with the historical revision. A lap index alone, an auto lap, a different historical prescription, or a missing revision cannot authorize a step-specific conclusion. Distinct ordered time or distance boundaries may be `estimated`; repeated indistinguishable boundaries remain `unmatched`. Estimated mapping never emits a work or cooldown volume finding.

The paired 35-to-44-minute tests distinguish nine extra minutes in cooldown from nine extra minutes in work. Session totals, individual step distance and timer deltas, lap average variation, missing repeats and unmatched recording tails are separate facts. A partial detail record uses the activity summary for the session total and labels its smaller recorded timer subtotal. Time within a historical numeric Target range uses only complete recorded FIT samples with valid intervals; paused intervals, gaps over 30 seconds, missing values and sampled charts are excluded. Facts expose the eligible step timer denominator and covered seconds. Neither RPE nor physiological cause is inferred.

Historical prescription queries now return their revision ID. Analysis persistence accepts snapshots from multiple explicitly listed activities owned by the same user, while still rejecting foreign or undeclared activity snapshots. Manual activities remain valid for summary-only analysis, but Task 2's detail-analysis persistence still requires at least one owned provider snapshot; Task 6 will decide how to present sparse/manual sessions without fabricating detail evidence.

The exact step examples are synthetic FIT fixtures. The earlier three live activity probes did not establish a historical step link, so no real-account activity has been labeled exact by this task. No live database row or Garmin resource was changed or fetched during Task 5 verification.

Verification: the full backend suite passed **830 tests** with 10 PostgreSQL-only skips in the default environment. On a freshly migrated disposable PostgreSQL database, the full suite passed **840 tests with 0 skips**; that database was dropped afterward. Both runs reported two pre-existing dependency deprecation warnings.
